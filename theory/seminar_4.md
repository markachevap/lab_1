

Семинар 4. Основы OpenMP
## 1  Введение
OpenMP представляет собой библиотеку и модификацию компилято-
ра. OpenMP использует модель общей памяти, к которой имеют доступ
все процессоры. При написании программ на OpenMP широко исполь-
зуются директивы препроцессора.
Данная библиотека совместно с MPI формирует «золотой стандарт» в
мире высокопроизводительных вычислений: в то время как MPI исполь-
зуется для организации коммуникаций между узлами кластера, отдель-
ные компьютеры в рамках гетерогенной системы используют OpenMP
для многопоточных вычислений.
Т.к. OpenMP не только библиотека, но и расширения компилятора,
отдельные компиляторы могут не поддерживать эту библиотеку. Если
компилятор не поддерживает OpenMP, то все директивы, адресованные
этой библиотеки, будут компилятором игнорироваться. Однако вызов
функций из состава OpenMP приведет к ошибке компиляции. Поэтому
для написания портабельного кода нужно заключать вызовы функций
OpenMP в блок условной компиляции:
#ifdef _OPENMP
//  c a l l  to OpenMP functions
## #endif

Структурный блок представляет собой одну или несколько команд. В
случае, если операторов больше одного, их нужно заключить в опера-

Директива barrier позволяет осуществить барьерную синхрониза-
цию между всему потоками. Отметим, что директивы parallel, parallel
for и for (о двух последних поговорим позже) содержат в себе неявный
барьер в конце структурного блока. Поэтому в листинге 1 нет явного
барьера после структурного блока: главный поток будет ждать, пока все
остальные потоки завершат свою работу.

3  Критические секции
При изменении общей переменной несколькими потоками возника-
ет состояние гонки, что приводит к искажению результатов. Состояние
гонки возникает в том случае, когда второй поток начинает изменять
переменную после того, как первый поток начал ее изменять, но до того,
как первый поток закончил.
Проиллюстрируем механизм возникновения состояния гонки на при-
мере сложения двух чисел с помощью операции sum += a, где sum —
общая переменная. См. таблицу 1.
Часть кода, одновременное выполнение которой несколькими потока-
ми приводит к возникновению состояния гонки, называется критической
секцией. В OpenMP существует несколько способов исключить одновре-
менное выполнение критической секции несколькими потоками. Самый
простой способ — использование директивы #pragma omp critical.

Следующий фрагмент кода
global_result = 0 . 0 ;
#pragma omp  p a r a l l e l  num_threads ( thread_count )
## {
double my_result = 0 . 0 ;
my_result += f ( ) ;

global_result += my_result ;

является часто используемым паттерном и может быть идиоматически
записан в следующем виде:
global_result = 0 . 0 ;
#pragma omp  p a r a l l e l  num_threads ( thread_count )\
reduction (+:  global_result )
global_result += f ( ) ;
Данная более компактная запись называется редукцией сложения по
переменной global_result. Редукция может быть применена не только
к сложению, но и вообще к любой бинарной ассоциативной операции:
арифметической, логической или побитовой.
Синтаксис директивы редукции: reduction(op : var_list),
где op — операция (+, -, *, /, &&, &, |, ||, ˆ);
var_list — список переменных редукции через запятую.
Редукция работает следующим образом. В случае изменения одной
из переменных из списка var_list создается временная приватная пере-
менная, инициализируемая нейтральным элементом по операции op и все
дальнейшие действия происходят с приватной переменной. После того,
как все потоки завершают работу, в общую переменную под директивой
critical записываются результаты каждой из приватных переменных,
причем к ним применяется операция редукции op. Исключение состав-
ляет вычитание. В этом случае к частичным результатам все равно при-
меняется сложение.
Проиллюстрируем применение директивы critical и редукции к за-
даче вычисления значения определенного интеграла. См. листинг 2.
